# CorianderPHP 0.3.0 contract

Tracking: https://github.com/CorianderPHP/CorianderPHP/issues/162. Implementation PRs target `0.3.0`; the completed release targets `main`.

## Routes

The default router discovers `src/Routes/**/*.method.php`. `index.get.php` maps to its directory root. `users/[id].get.php` maps GET `/users/42`; `teams/[teamId]/users/[id].post.php` maps POST `/teams/7/users/42`. Method suffixes are lowercase `get`, `post`, `put`, `patch`, `delete`, `head`, or `options`. Files without a suffix and reserved files beginning with `_` are not handlers.

Paths are case-sensitive. A trailing slash is accepted, duplicate internal slashes are rejected, and each segment is URL-decoded once. Encoded separators, dot segments, backslashes and NUL bytes are rejected. Static segments outrank dynamic segments regardless of method: `/users/new` does not fall through to `/users/[id]` for another method. Structurally identical dynamic patterns must use the same parameter names; duplicate path/method definitions are errors.

Handlers return a callable accepting `ServerRequestInterface` and returning `ResponseInterface`. Captured path parameters are request attributes. No controller classes or manual route-registration files are required. No handler is executed during discovery; only the selected handler is loaded during dispatch. GET supplies HEAD unless a HEAD handler exists. Unsupported methods return 405 with `Allow`; missing paths return 404. The emitter never sends a HEAD body.

```php
<?php // src/Routes/users/[id].get.php
use CorianderCore\Core\Http\Responses;
use Psr\Http\Message\ServerRequestInterface;

return static fn(ServerRequestInterface $request) =>
    Responses::json(['id' => $request->getAttribute('id')]);
```

## Requests and responses

`RequestFactory::fromGlobals()` populates queries, cookies, uploads and parsed form/JSON bodies. Parameters, query fields and body fields remain separate. Malformed JSON is a 400 error. `Responses::html()`, `json()`, `redirect()` and `view()` return existing PSR response objects, preserving status and headers. Templates and route handlers should not mutate global HTTP headers or print handler responses.

```php
<?php // src/Routes/users/[id].post.php
use CorianderCore\Core\Http\Responses;
use Psr\Http\Message\ServerRequestInterface;

return static function (ServerRequestInterface $request) {
    $body = $request->getParsedBody();
    if (!is_array($body) || !is_string($body['name'] ?? null)) {
        return Responses::json(['error' => 'A name is required'], 422);
    }
    // Validate authorization and persist through application services here.
    return Responses::redirect('/users/' . rawurlencode($request->getAttribute('id')));
};
```

## Middleware

`src/Routes/_middleware.php` and ancestor `_middleware.php` files return ordered arrays of PSR-15 middleware instances. Middleware accumulates root to leaf; children cannot disable inherited middleware. Files are loaded for each request so editing their contents does not depend on route cache refresh. Their existence is checked along the selected route's complete ancestor chain, including files added after the map was built. Missing/invalid middleware is never silently ignored when it was previously registered.

```php
<?php // src/Routes/admin/_middleware.php
return [new \App\Middleware\Authenticate()];
```

Global HTTP security headers, CSRF and request limits remain available through the bootstrap. Session-authenticated mutations require CSRF regardless of HTML/JSON output. A stateless API exclusion must be explicit; there is no implicit `/api` exemption in the starter. Middleware can return a response or call the next PSR handler. Route attributes are available to directory middleware.

## Views and layouts

`Responses::view('admin/dashboard', $data)` renders `src/Views/admin/dashboard.php`. The renderer chooses the nearest complete `_header.php`/`_footer.php` pair in the view's ancestry, independently of route ancestry. Nested layouts replace parent layouts. Any encountered incomplete pair is an error. No pair means bare rendering. `layout: false` produces a fragment and skips layout discovery. String data is escaped for HTML without permitting it to overwrite renderer variables. Header, template and footer share view data and render afresh on each call. Views are never exposed as routes automatically.

## Automatic cache

`APP_ENV=production` uses a PHP route map rebuilt automatically on the first request and rechecked after 30 seconds. Other environments rediscover on each request. Only data is cached: paths, methods, parameter patterns and ancestor directories. A nonblocking file lock permits one refresh; other requests may use the last valid map. First-build contention must wait for a complete map. Writes use temporary files and atomic replacement with OPcache invalidation. Unwritable cache storage falls back to discovery, keeping the app usable; invalid route definitions fail instead of publishing partial maps. A disappeared handler or previously known middleware file fails closed and does not fall through to another route. Refresh intervals affect new/renamed routes; deployment with OPcache timestamp validation disabled still requires the host's normal OPcache lifecycle handling.

## Validation and migration

Benchmark discovery, cached startup, repeated dispatch, middleware/layout overhead and HTTP responses separately. Use 10, 100 and 1,000 routes, validate status/body, repeat runs and record PHP/OS/OPcache. Timing is reported, not used as a flaky shared-runner pass/fail gate. Correctness tests enforce no discovery on valid-cache ordinary requests and no handler execution during discovery.

Move controller actions to method files returning callables and extract reusable logic into ordinary app classes. Move templates from `public/public_views` to `src/Views`, rename shared layouts and replace metadata includes with explicit view data. Replace `public/routes.php` registrations with route files. Update bootstrap, Composer application namespace mappings and web-server configuration manually where the updater preserves app-owned files. Database, migrations, logging and sessions are not redesigned. Catch-all/optional params and automatic model binding are deferred. No new runtime dependencies are planned.
