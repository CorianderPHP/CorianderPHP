# 0.3.0 stabilization roadmap

Keep the runtime light: reuse PHP and existing PSR facilities, add no runtime dependencies, and optimize measured bottlenecks. Each item uses one issue and PR, starts from the latest `main`, and merges only after its checks pass. Delete the completed branch before starting the next.

1. Reject oversized request bodies before parsing (#190): bounded reads, declared/actual size checks and HTTP 413 coverage.
2. Finish HTTP response emission (#192): bodyless statuses and correct framing headers, preserving HEAD behavior.
3. Make development errors useful (#194): explicit local debug mode with escaped exception details and generic production errors.
4. Record a production benchmark baseline (#196): PHP-FPM, OPcache, concurrent clients, session-backed requests and individual request latency percentiles.
5. Reduce unnecessary sessions (#198): start on demand for authentication, CSRF or application code; measure concurrent session requests and document migration.
6. Add `routes:list` (#200): reuse discovery without executing route or middleware files; display method, path, handler and inherited middleware.
7. Review unused code and starter boilerplate (#202): remove the unused container, keep generated views session-free and explain the public API removal.
8. Align useful comments and documentation: native types first, precise collection types, public contracts and comments explaining decisions. Update `AGENTS.md` and migration/release guidance.

Run focused checks first, then the full relevant CI. Production benchmarks verify responses and report environment, throughput, latency and memory limitations; they do not claim speed advantages from unrelated environments or use unstable absolute CI timing gates. Comments should help maintainers understand constraints, not repeat the implementation.
