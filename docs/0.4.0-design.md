# Unified pages: 0.4.0 contract

This document records the implemented 0.4.0 contract and its ordered delivery. See the [migration guide](migration-0.4.0.md) for application changes and the [release notes](release-notes-0.4.0.md) for user-visible behavior.

## One application tree

`src/Views` contains pages and HTTP handlers. There is no default `src/Routes` tree. Keep `public` as the web-server document root, containing the front controller and public assets. Application classes remain under `src` with the `App\` namespace.

```text
src/Views/
  _middleware.php
  _metadata.php
  _header.php
  _footer.php
  index.get.php
  about/index.get.php
  users/[id].get.php
  users/[id].post.php
  teams/[team]/users/[id].get.php
```

Method suffixes are lowercase `get`, `post`, `put`, `patch`, `delete`, `head`, and `options`. `index.get.php` maps to its directory root. `users/[id].get.php` maps GET `/users/42`. `users/[id]/index.get.php` is an equivalent path and provides a directory for local helpers. Defining both for the same method is an error. Unsuffixed PHP files are not endpoints. Names starting with `_` or `.` are excluded from discovery.

Static paths take priority; a static method mismatch does not fall through to a dynamic endpoint. Missing paths return 404; unsupported methods return 405 with `Allow`. GET supplies HEAD when no explicit HEAD exists; HEAD emits no body. Discovery and `routes:list` inspect filenames without executing app code.

## Execution

GET files may contain PHP/HTML directly. The framework exposes `$request` as a `ServerRequestInterface`, executes the selected file once, captures its output, and constructs an HTML response before emission. Route parameters remain request attributes; they are not extracted into arbitrary local variables.

```php
<!-- src/Views/about/index.get.php -->
<h1>About us</h1>
<p>Text and images need no forwarding handler.</p>
```

```php
<!-- src/Views/users/[id].get.php -->
<h1>User <?= htmlspecialchars((string) $request->getAttribute('id'), ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8') ?></h1>
```

Any method file may instead return a callable accepting the request and returning a PSR response. This includes GET redirects and JSON. Non-GET files must use this contract; printed output from handlers or middleware is an error. A file that prints HTML and returns a handler is also an error. Invalid return values fail with the source filename. Explicit responses are not automatically decorated with metadata or layouts. Metadata is evaluated before GET files so it is available to direct templates; keep declarations free of side effects. Non-GET dispatch skips metadata unless its handler explicitly renders a view.

```php
<?php // src/Views/users/[id].post.php
use CorianderCore\Core\Http\Responses;
use Psr\Http\Message\ServerRequestInterface;

return static function (ServerRequestInterface $request) {
    // Validate submitted data and delegate persistence to application code.
    return Responses::redirect('/users/' . rawurlencode((string) $request->getAttribute('id')));
};
```

```php
<?php // src/Views/home.get.php
use CorianderCore\Core\Http\Responses;
return static fn($request) => Responses::redirect('/');
```

```php
<?php // src/Views/api/users.get.php
use CorianderCore\Core\Http\Responses;
return static fn($request) => Responses::json(['users' => []]);
```

## Middleware, layouts and metadata

Directory `_middleware.php` declarations return PSR-15 middleware arrays. They accumulate root to leaf, run before page execution and receive matched parameters. Children cannot disable inherited middleware. Cached missing middleware fails closed. Existing CSRF, body limits, lazy sessions and response emission rules remain in force.

Resolve `_header.php` and `_footer.php` independently from the closest ancestor. Each part appears at most once; absent parts are omitted. Direct pages and layouts receive `$request` and `$page`; page-local assignments are not forwarded to layouts. Explicit view rendering shares its data and retains `layout: false`.

Optional `_metadata.php` files return arrays, loaded root to leaf for HTML rendering. Parent defaults are shallowly replaced by child keys. The resulting array is available as `$page` before rendering the header. Missing files mean no metadata; malformed files identify their source in an error. Metadata must not print output. Application data cannot overwrite internal renderer variables or `$request`.

Existing explicit view data continues to be HTML-escaped recursively. Metadata string values follow the same rule. Values read directly from `$request` are raw and must be escaped for their output context; HTML escaping is not JavaScript or URL encoding. Do not escape already escaped view data again.

## Caching and performance

Reuse the data-only route map and automatic production refresh. No deployment build command is required. Do not execute application files during discovery or add runtime dependencies. Execute only the selected page and required ancestor helpers. Benchmark equivalent responses before and after the rework; shared CI timing is informational.

The updater preserves application-owned files; this migration is manual. The [benchmark guide](benchmarks.md) records verified equivalent responses and timing/memory limits.
